# Server Scripts environment

What the environment is, how URLs map to files, and what the platform allows. Facts marked
**(observed)** were read from a live account in October 2026. Per-account values (versions,
limits) can differ, so read the live values with the listed action instead of hard-coding them.

## 1. What it is

- A **DirectAdmin user account on CloudLinux**, created for one uCoz site and named `u{site_id}`
  (`status.username`). The package is a PHP-hosting plan (`user_config.package`, observed `ucozphp`).
- It is **separate from the uCoz CMS**. Templates, modules, and site storage stay in the CMS (other
  MCP tools). Server Scripts holds only your backend code and its data.
- Runtimes: PHP (CloudLinux PHP Selector), Node.js and Python (CloudLinux selectors + Passenger),
  MySQL, cron, FTP. The web server reads `.htaccess` and has LiteSpeed/Apache semantics.
- **Off (observed):** SSH, CGI, git, Redis, WordPress installer, shell functions in PHP. There is no
  way to run a command except via an HTTP request or a cron job.

## 2. Identities and domains

| Name | Where to read it | Meaning |
|---|---|---|
| `{site}` | `status.host` | The uCoz site domain (or the owner's custom domain). Users see this one. |
| `{username}` | `status.username` | DirectAdmin user. Also the MySQL name prefix. Home is `/home/{username}`. |
| `{tech}` | `status.domain` | Technical domain `{username}.usites.app`. Serves the same docroot directly. |
| `{domain}` | `session.selected_domain` / `files_list path=domains` | The **folder** under `domains/`. Usually equals `{tech}`. |

An account may have more than one domain (`usage.domains.limit`, observed 2). Always take `{domain}` from
`session`; never guess it.

## 3. Directory layout (home-relative, as `apps_read` / `apps_write` / `apps_delete` sees it)

```text
domains/{domain}/
├─ public_html/            docroot (private_html is a symlink to it)
│  ├─ index.html           default placeholder page created with the account
│  ├─ cgi-bin/             unused (CGI off)
│  ├─ <php-module>/        your PHP code, served at /apps/<php-module>/
│  └─ <app_uri>/.htaccess  generated by node_create/python_create (Passenger + SetEnv) — do not edit
├─ app_node/<name>/        Node app roots (not web-served directly)
├─ app_python/<name>/      Python app roots (not web-served directly)
├─ <name>_secrets.php      your PHP secrets, outside the docroot
├─ logs/                   rotated archives: <Mon-YYYY>.tar.gz[.N], nginx.<Mon-YYYY>.tar.gz[.N]
├─ public_ftp/, stats/     standard DirectAdmin folders
nodevenv/…, virtualenv/…   per-app runtime environments created by the selectors (do not touch)
.ucoz/conf/ucoz.conf       visitor key file (managed by visitor_key_*; never read/edit/print)
.php/php-mail.log          log of PHP mail() calls
```

Node/Python app roots also get `public/` and `tmp/` from `*_create`. `public/` is **not** served as static
files (requests reach the app); writing `tmp/restart.txt` reloads the app (verified).

Older notes (and the earlier community skill) put Passenger roots at `/home/{username}/app_node`
above an FTP jail. **On the current platform, app roots live under `domains/{domain}/app_node|app_python`,**
which the MCP guide confirms and the live account shows.

## 4. URL mapping (verified)

| File / app | Site URL (give this to users) | Technical URL |
|---|---|---|
| `public_html/foo/index.php` | `https://{site}/apps/foo/` | `https://{tech}/foo/` |
| `public_html/foo/bar.php` | `https://{site}/apps/foo/bar.php` | `https://{tech}/foo/bar.php` |
| `public_html/index.html` | `https://{site}/apps/index.html` | `https://{tech}/` |
| Node/Python app `app_uri=/plan` | `https://{site}/apps/plan/…` | `https://{tech}/plan/…` |
| `/apps/` root itself | 404 — not an entry point | — |

**What your code sees (verified).** The proxy strips `/apps`. A request to
`https://{site}/apps/foo/x?y=1` arrives as:

| Runtime | Path seen by code | Host header |
|---|---|---|
| PHP | `REQUEST_URI = /foo/x?y=1` | `{tech}` |
| Node | `req.url = /foo/x?y=1` (includes the app_uri) | `{tech}` |
| Python | `REQUEST_URI = /foo/x?y=1`, `SCRIPT_NAME = /foo`, `PATH_INFO = /x` | `{tech}` |

So code cannot tell the site URL from the technical URL by path or Host. Build public links from
config (`https://{site}/apps/{name}/`), never from `HTTP_HOST`. `X-Forwarded-For` is present
(the client IP is its first entry).

**Trailing slash traps (verified):**
- PHP folder without a slash: `https://{site}/apps/foo` → **301 to `https://{tech}/foo/`**. The visitor
  leaves the site domain and loses identity. Always link to `/apps/foo/`.
- Node app without a slash: `/apps/plan` → 200 (no redirect). Relative asset URLs then resolve against
  `/apps/` and break. Use absolute asset URLs (`/apps/plan/ui.css`).

Other notes:
- The uCoz proxy adds the encrypted visitor identity header (`X-Ucoz-User`) only to requests that go
  through `https://{site}/apps/…`. On `{tech}`, every visitor is a guest. See IDENTITY.md.
- Because `/apps/…` is on the site's own origin, JavaScript in uCoz templates can call it with
  `fetch('/apps/foo/api/…')` **with no CORS setup**.

## 5. Runtimes (observed — read live with the listed action)

| Runtime | Versions | Default | Read with |
|---|---|---|---|
| PHP | 7.4, 8.2, 8.3, 8.4, 8.5, "native (8.3)" | 8.3 | `php_get` (large — summarize) |
| Node.js | 20, 22, 24 | 22 | `node_list` |
| Python | 3.7, 3.11, 3.12, 3.13 | 3.11 | `python_list` |

**PHP 8.3 extensions (observed).** Built in: curl, openssl, json, pcre, session, sqlite3, zlib,
iconv, gettext, exif, ftp, hash, random, simplexml, tokenizer, ctype, filter. Enabled:
bcmath, dom, ffi, fileinfo, gd, imagick, imap, intl, mbstring, mysqlnd, nd_mysqli, nd_pdo_mysql,
pdo, pdo_mysql, pdo_sqlite, phar, posix, soap, sockets, sodium, sysv*, xmlreader, xmlwriter, xsl,
zip. Disabled: opcache (edits are live immediately), apcu, redis, memcached, xdebug, and others.
Use `mysqli`/`PDO` as usual — the `nd_*` variants provide them. Design around what is enabled; extensions
cannot be changed through MCP. Disabled functions: PHP.md §5.

**Node / Python (observed):** Passenger 6.0.26; Node 22.23 at `/opt/alt/alt-nodejs22/root/usr/bin/node`;
Python 3.11 in `~/virtualenv/domains/{domain}/app_python/{name}/3.11/`. MySQL server: MariaDB 10.6.

**PHP options (selector defaults, observed):** `memory_limit 128M` (up to 512M),
`upload_max_filesize 2M` (up to 1G), `post_max_size 8M` (up to 128M), `max_execution_time 30`,
`display_errors Off`, `log_errors On`, `allow_url_fopen On`, `error_reporting E_ALL`.
`ini_set()` works for runtime options such as `memory_limit`, `error_log`, `display_errors`.
Upload limits are not runtime-settable — see PHP.md §Uploads.

## 6. Limits (observed — always read `usage` / `user_config`)

| Resource | Observed limit | Action |
|---|---|---|
| Disk quota | 500 MB | `usage.quotaBytes` |
| Inodes (files + dirs) | 50 000 | `usage.inode` |
| Bandwidth | 50 GB / month | `usage.bandwidthBytes` |
| MySQL databases | 3 | `usage.mySqlDatabases` |
| FTP accounts | 3 (one exists by default) | `usage.ftpAccounts` |
| Domains / subdomains / pointers | 2 / 5 / 3 | `usage` |
| Max file size in the panel | 500 MB | `session.directadminConfig.maxFilesizeBytes` |
| **Request time** | **~60 s** — nginx answers `504 Gateway Time-out` (Node and Python verified: 55 s OK, 65 s → 504); PHP stops earlier at `max_execution_time` 30 s | — |

Timing (measured from a client, incl. TLS): Node/Python cold start or first request after a reload ~2.5 s,
warm requests ~0.6 s, respawn after a crash ~4.5 s. A small Node app uses ~75 MB RSS.

**Consequence:** no request may run long. Imports of big catalogs, rebuilds, mass sends go into cron jobs
that process a batch per run and keep a cursor (CRON.md).

`node_modules` and Python packages eat inodes fast. Check `usage.inode` before installing packages
and prefer the standard library.

## 7. What the agent can and cannot do through MCP

| Can | Cannot |
|---|---|
| Read/write/patch text files, mkdir, copy, move, chmod, search, archive, extract | Upload binary files (write text only) |
| Create/restart Node and Python apps, install npm deps | Run shell commands, SSH, git (a cron job can run a command once — e.g. Python `pip`, PYTHON.md §5) |
| Create databases and users, change passwords/privileges | Execute SQL (use code migrations or the phpMyAdmin link) |
| Create/list/delete cron jobs | Read Passenger logs or console/`print` output (`passenger_log_file` is `null`) — write your own log files; PHP: `ini_set('error_log')` |
| Create backups and public download links | Buy or extend the service; install Python packages via `python_install_modules` |
| Manage the visitor key (identity) and login keys | Change `env_vars` after `*_create` |
